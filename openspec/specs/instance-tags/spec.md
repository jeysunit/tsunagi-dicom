# instance-tags Specification

## Purpose
検査一覧の詳細のパネルで、シリーズのサムネイルから、そのシリーズの画像ごとに DICOM タグを見る機能を定める。
出すタグは施設が設定で決め、値の全部も同じ場所で見られる。読み取りだけで、権限の確かめと操作ログを通す。

## Requirements

### Requirement: サムネイルからシリーズの画像の場所を開く

すべての DICOM の値を見る権限（`dicom.all_values`）のある利用者が詳細のパネルのシリーズのサムネイルを押したとき、画面はサムネイルの並びの下に、そのシリーズの画像の場所を開かなければならない（SHALL）。押したサムネイルは選んだ形（`aria-pressed`）で示す。

#### Scenario: サムネイルを押して開く

- **WHEN** 一般の役割の利用者が、検査の詳細のパネルで 2 番目のシリーズのサムネイルを押す
- **THEN** サムネイルの並びの下に、そのシリーズの画像の一覧と、先頭の画像のタグが出て、2 番目のサムネイルが選んだ形になる

#### Scenario: 別のサムネイルに替える

- **WHEN** 画像の場所が開いているときに、別のシリーズのサムネイルを押す
- **THEN** 画像の場所は押したシリーズの中身に替わり、その先頭の画像を選ぶ

#### Scenario: 同じサムネイルで閉じる

- **WHEN** 画像の場所が開いているときに、選んでいるサムネイルをもう一度押す
- **THEN** 画像の場所が閉じ、どのサムネイルも選んだ形でなくなる

#### Scenario: 行を替えると閉じる

- **WHEN** 画像の場所が開いているときに、検査一覧で別の行を選ぶ
- **THEN** 新しい行の詳細のパネルでは、画像の場所は閉じている

#### Scenario: キーボードで開く

- **WHEN** 利用者がサムネイルにフォーカスを移し、Enter か Space を押す
- **THEN** 押したときと同じく画像の場所が開く

### Requirement: 権限の無い役割にはサムネイルを押せる形にしない

`dicom.all_values` の無い役割では、サムネイルは押せる形（ボタン）にしてはならず（SHALL NOT）、いまと同じ見た目の絵として出す。画面の API は、権限の無い要求を 403 で断り、断ったことも操作ログに残さなければならない（SHALL）。

#### Scenario: 権限の無い役割の画面

- **WHEN** `dicom.all_values` を割り当てから外した役割の利用者が詳細のパネルを開く
- **THEN** サムネイルはボタンではなく、押しても何も開かない

#### Scenario: 権限の無い役割が画面の API を呼ぶ

- **WHEN** `dicom.all_values` の無い役割の利用者が、画像のタグの画面の API を直に呼ぶ
- **THEN** 403 が返り、値は返らず、操作ログに断った記録が残る

### Requirement: 画像の一覧

画像の場所は、シリーズの画像を画像の番号（InstanceNumber）の順に並べ、1 行に画像の番号を出さなければならない（SHALL）。複数フレームの画像には、フレームの数を添える。画像の番号が無い画像は SOPInstanceUID で出す。一覧は上下の矢印のキーで選ぶ画像を替えられる。

#### Scenario: 番号の順に並ぶ

- **WHEN** 画像の番号が 3・1・2 の画像を持つシリーズの画像の場所を開く
- **THEN** 一覧は #1・#2・#3 の順に並び、#1 を選んでいる

#### Scenario: 複数フレームの画像

- **WHEN** フレームの数が 30 の画像を含むシリーズを開く
- **THEN** その画像の行に「30 フレーム」が添えて出る

#### Scenario: 矢印のキーで替える

- **WHEN** 一覧にフォーカスがあり、#1 を選んでいるときに下の矢印のキーを押す
- **THEN** #2 を選び、右のタグが #2 の値に替わる

#### Scenario: 画像の無いシリーズ

- **WHEN** 画像の一覧が空のシリーズを開く
- **THEN** 「画像がありません」と出て、タグの表は出ない

### Requirement: 設定のタグを、設定の順に出す

画像の場所の「主なタグ」は、設定（`INSTANCE_TAGS`、無ければ既定の一覧）に書いたタグだけを、書いた順に、タグ・タグ名・VR・値の表で出さなければならない（SHALL）。画像に無いタグも行を出し、値を「—」にする。画面の API は、設定に無いタグの値を返してはならない（SHALL NOT）。

#### Scenario: 設定の順に出る

- **WHEN** `INSTANCE_TAGS="(0020,0013) (0008,0018) (0028,0010)"` で起動し、画像の場所を開く
- **THEN** 表は (0020,0013)・(0008,0018)・(0028,0010) の 3 行だけを、この順に出す

#### Scenario: 画像に無いタグ

- **WHEN** 設定に (0018,0050) があり、選んだ画像に SliceThickness が無い
- **THEN** (0018,0050) の行が出て、値は「—」になる

#### Scenario: 設定に無いタグは返らない

- **WHEN** 設定に (0010,0010) が無い状態で、画像のタグの画面の API を呼ぶ
- **THEN** 答えに (0010,0010) の行は無い

#### Scenario: タグ名は日本語

- **WHEN** 既定の一覧で画像の場所を開く
- **THEN** (0020,0013) の行のタグ名は「画像番号」、(0028,0010) の行は「行数」と、日本語で出る

#### Scenario: タグ名の無いタグ

- **WHEN** 設定に、tsunagi-dicom がタグ名を持たないタグ（私的タグなど）がある
- **THEN** その行はタグ名を空にして、タグ・VR・値を出す

### Requirement: 主なタグとすべてのタグを切り替える

画像の場所は「主なタグ」と「すべてのタグ」の切り替えを持たなければならない（SHALL）。既定は「主なタグ」。「すべてのタグ」は、選んだ画像の値の全部をタグの順に出す。切り替えは、画像やシリーズを替えても保つ。

#### Scenario: すべてのタグに切り替える

- **WHEN** 画像の場所で「すべてのタグ」を押す
- **THEN** 選んだ画像の値の全部が、タグの順に出る

#### Scenario: 画像を替えても保つ

- **WHEN** 「すべてのタグ」を選んだまま、一覧で別の画像を選ぶ
- **THEN** 別の画像の値の全部が出る

### Requirement: 「DICOM タグ」は検査単位だけにする

詳細のパネルの開け閉めの「DICOM タグ」は、検査単位（要約）の値だけを出し、検査単位と画像単位の切り替えを持ってはならない（SHALL NOT）。画像ごとの値は、サムネイルから開く画像の場所で見る。

#### Scenario: DICOM タグを開く

- **WHEN** 権限のある利用者が「DICOM タグ」を開く
- **THEN** 検査単位（要約）の値の表が出て、「画像単位」の切り替えは無い

### Requirement: 値の出し方

値は文字として出し、HTML として解いてはならない（SHALL NOT）。複数の値は `\` でつなぐ。人の名前（PN）は DICOM の形（`Alphabetic=Ideographic=Phonetic`）でつなぐ。画面の API は、Orthanc が文字コード（SpecificCharacterSet）に従って Unicode に直した値をそのまま返し、BFF の側で文字コードを読み替えない。

#### Scenario: 日本語の値

- **WHEN** SpecificCharacterSet が `\ISO 2022 IR 87` の画像で、PatientName が設定にある
- **THEN** 値は漢字とかなが読める形（例 `YAMADA^TARO=山田^太郎=やまだ^たろう`）で出る

#### Scenario: HTML の形の値

- **WHEN** ImageComments の値が `<b>x</b>` の画像を開く
- **THEN** 値は `<b>x</b>` の文字のまま出て、太字にならない

### Requirement: 長い値とバイナリの値

画面の API は、1 つのタグの値の文字の列が 1024 文字を超えるとき、先頭の 1024 文字と全体の文字数を返さなければならない（SHALL）。画面は値に続けて「…（全 N 文字）」を出す。バイナリの値（VR が OB・OD・OF・OL・OV・OW・UN のもの、または InlineBinary・BulkDataURI のもの）は中身を返さず「（バイナリ）」とし、BulkDataURI を読みに行ってはならない（SHALL NOT）。シーケンス（SQ）は「（シーケンス N 件）」と出す。

#### Scenario: 長い値

- **WHEN** 値が 5000 文字のタグが設定にある画像を開く
- **THEN** 値は先頭の 1024 文字で、続けて「…（全 5,000 文字）」が出る

#### Scenario: バイナリの値

- **WHEN** 設定に (7FE0,0010) がある
- **THEN** その行の値は「（バイナリ）」で、画像サーバーへ画素のデータを求めない

#### Scenario: シーケンス

- **WHEN** 設定に、項目が 2 件のシーケンスのタグがある
- **THEN** その行の値は「（シーケンス 2 件）」になる

### Requirement: 出すタグの一覧の設定

出すタグは環境変数 `INSTANCE_TAGS` に、タグの番号を空白で区切って書けなければならない（SHALL）。1 つの番号は `(gggg,eeee)`・`gggg,eeee`・`ggggeeee` のどの形でもよく、16 進の大文字と小文字を区別しない。空か未設定なら既定の一覧を使う。形の誤り・重なり・100 個を超える数は、変数の名前と誤りを並べて起動を断る。

#### Scenario: 3 つの形が混ざる

- **WHEN** `INSTANCE_TAGS="(0008,0018) 0020,0013 00280010"` で起動する
- **THEN** 起動し、3 つのタグをこの順に出す

#### Scenario: 未設定

- **WHEN** `INSTANCE_TAGS` を書かずに起動する
- **THEN** 既定の一覧（25 のタグ）を出す

#### Scenario: 形の誤り

- **WHEN** `INSTANCE_TAGS="(0008,001G)"` で起動する
- **THEN** 起動せず、`INSTANCE_TAGS` の誤りとして、形の誤った番号が示される

#### Scenario: 重なり

- **WHEN** `INSTANCE_TAGS="00080018 (0008,0018)"` で起動する
- **THEN** 起動せず、重なったタグが示される

### Requirement: 読み取りだけと操作ログ

画像の一覧とタグの読み取りは、BFF が画像サーバーへ読み取りだけを求めなければならない（SHALL）。ブラウザから画像サーバーへの道（中継）は足さない。読むたびに、操作ログに `view_study` を残し、`detail` に `level`・SeriesInstanceUID・SOPInstanceUID と、出したタグの組（`set`：`configured` か `all`）を書く。

#### Scenario: 主なタグを読んだ記録

- **WHEN** 利用者が画像の場所で #2 の画像を選ぶ
- **THEN** 操作ログに `view_study` の行が足され、`detail` に `level: "instance"`・その画像の SOPInstanceUID・`set: "configured"` が入る

#### Scenario: 中継からは読めない

- **WHEN** ブラウザが BFF の中継（`/api/dicom-web/...`）に画像の単位の QIDO-RS を求める
- **THEN** 中継は断り、断ったことを記録する（いまの決まりのまま）
