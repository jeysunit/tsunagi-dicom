# Design

## Context

動機は proposal.md の Why。いまの形のうち、この設計に効くものは次のとおり。

- 詳細のパネル（`src/components/studies/study-detail.tsx`）は、検査一覧の下の場所に出る。シリーズのサムネイルは `<li>` の中の絵で、押しても何も起きない。
- 「DICOM タグ」の画像単位は、すでに画像の並び（`GET …/series/{series}/instances`、BFF の QIDO-RS）と、1 枚の値の全部（`GET …/instances/{sop}/values`、BFF の WADO-RS の `metadata`）を持つ。どちらも `dicom.all_values` で、読むたびに `view_study` を残し、画面は読み直す間に前の値を出さない（`staleTime: 0`・`gcTime: 0`）。
- 設定は環境変数を `src/lib/config.ts` が起動の時に zod で確かめ、誤りを `ConfigError` で並べて起動を断る。管理の画面で変える設定は、ビューア設定（モダリティごとの既定のビューア。データベースに持ち、`viewer.defaults`）の 1 つだけ。
- 役割は管理者と一般の 2 つで、`dicom.all_values` は両方に割り当てている（`src/lib/auth/roles.ts`）。
- 画面の言葉は `docs/spec.md` の 2.2 の用語集から選び、説明の文を画面に置かない。

## Goals / Non-Goals

**Goals:**

- サムネイルを押すだけで、そのシリーズの画像の一覧と、施設が決めたタグを見られる。
- 画像単位の値を見る場所を 1 つにする（いまの「DICOM タグ」の画像単位を、サムネイルから開く場所へ移す）。
- 画像サーバーへの要求の種類を増やさない（BFF の QIDO-RS と WADO-RS の `metadata` だけ）。

**Non-Goals:**

- 画像（画素）を画像の場所に出すこと。画像はビューアで見る。
- タグの値の修正（`docs/spec.md` の 3.5 の「値の修正」は別の段）。
- シーケンス（SQ）の中を開いて見ること。件数だけを出す。
- 出すタグを利用者ごとに変えること。施設で 1 つの一覧にする。

## Decisions

### 1. 画面の流れ：詳細のパネルの中に、画像の場所を開く

サムネイルを押すと、サムネイルの並びの下に画像の場所を開く。頁は移らない。

```text
検査一覧
└─ 詳細のパネル（選んだ行）
   ├─ 見出し 2 行・ビューア・PACS の操作
   ├─ シリーズのサムネイル（横に 1 列）  ← 押すと選んだ形になり、下に画像の場所を開く
   ├─ 画像の場所（開いたときだけ）
   │   ├─ 見出し：#番号 シリーズ名・画像数　［主なタグ｜すべてのタグ］
   │   ├─ 左：画像の一覧（#1、#2（30 フレーム）…）  ← 上下の矢印のキーで替える
   │   └─ 右：SOPInstanceUID（コピー）とタグの表（タグ・タグ名・VR・値）
   └─ 開け閉めの「UID」「DICOM タグ」（DICOM タグは検査単位だけ）
```

- 幅が 768px 未満のときは、左右に分けず、画像の一覧を上、タグの表を下に重ねる。
- 画像の一覧とタグの表は、それぞれの中でスクロールする（パネルの高さを越えない）。
- 別の案は、シリーズごとの頁（`/studies/{uid}/series/{series}`）へ移る形。広く使えて URL で開けるが、選んだ行と絞り込みの位置を離れ、戻ると選んだ行が残らない（選んだ行は頁の URL に持っていない）。詳細のパネルの「行を選ぶと動きの遅れ無しに替わる」使い方とも合わないので採らない。

### 2. 「DICOM タグ」の画像単位を、画像の場所の「すべてのタグ」へ移す

画像の場所に「主なタグ」と「すべてのタグ」の切り替えを置き、「DICOM タグ」の中の「検査単位（要約）・画像単位」の切り替えを外す。同じ「シリーズ → 画像 → 値の全部」を出す場所を 2 つ持たないため。

- 別の案は、「DICOM タグ」の画像単位を残す形。変更は小さいが、シリーズと画像を選ぶ欄が 2 か所にでき、どちらで見るかを利用者が迷う。

### 3. 設定の置き場：環境変数 `INSTANCE_TAGS`

出すタグの一覧は、`.env.example` に載せる環境変数 `INSTANCE_TAGS` にする。`src/lib/config.ts` の `screen` に `instanceTags: string[]`（8 桁の大文字の 16 進。`00080018` の形）を足す。

- 形：番号を空白で区切る。1 つの番号は `(gggg,eeee)`・`gggg,eeee`・`ggggeeee` のどれでもよい。番号の中の `,` と区切りがぶつからないよう、区切りは空白だけにする。
- 確かめ：形の誤り・重なり・100 個を超える数を、起動の時に `ConfigError` で断る（ほかの変数と同じく、どの番号が誤りかを示す。秘密ではないので値を示してよい）。
- 空か未設定なら既定の一覧（下の 5）を使う。
- 別の案は、管理の画面（ビューア設定と同じく、データベースに持ち、管理者が変える）。再起動なしで変えられるが、表・migration・画面・設定の変更の操作ログ・試験が要り、変える頻度（施設で導入の時に一度決める）に見合わない。画面で変えたいという要望が出たら、そのときに管理の画面へ移す（設定の変数は既定値として残せる）。

### 4. Orthanc の API：いまの WADO-RS の `metadata` を使い、REST の `/tags` は使わない

選んだ画像の値は、いまの `Backend.instanceDataset`（BFF が DICOMweb のプラグインの `studies/{study}/series/{series}/instances/{sop}/metadata` を読み、3 つの UID が求めたものと同じときだけ返す）で読み、BFF が設定のタグだけを選び出して返す。画像の一覧は、いまの `Backend.searchInstances`（QIDO-RS）を使う。

- 別の案 1：Orthanc の REST の `/instances/{id}/tags?short`（キーが `0008,0018` の形）。Orthanc の ID が要るので、SOPInstanceUID から `/tools/lookup` で引く 1 回が増える。読み取りの値を DICOMweb で読む決まり（`docs/spec.md` 原則 2）からも外れる。
- 別の案 2：`/instances/{id}/simplified-tags`。キーがタグの名前で、番号で決める設定と合わず、私的タグ・同名のタグを扱えない。採らない。
- 別の案 3：画像の一覧の QIDO-RS に `includefield` で設定のタグを足し、一覧に値を並べる。Orthanc は索引に無いタグを画像ごとにファイルから読むため、画像の多いシリーズで遅くなる。採らない。

### 5. 既定のタグの一覧（25）

画像の確認（どの画像か・いつ撮ったか・位置と向き・大きさと画素・表示の値・圧縮）に普通使うもの。

「タグ名」は画面に出す日本語の名前の案（7 を見る）。* は参考の訳（7 の出典）から変えたもの。

| タグ | keyword | タグ名 | 見るもの |
|---|---|---|---|
| (0008,0018) | SOPInstanceUID | SOPインスタンスUID | どの画像か |
| (0008,0016) | SOPClassUID | SOPクラスUID | 画像の種類 |
| (0020,0013) | InstanceNumber | 画像番号 * | 画像の番号 |
| (0008,0008) | ImageType | 画像タイプ | ORIGINAL・DERIVED など |
| (0020,0012) | AcquisitionNumber | 収集番号 | 撮影の番号 |
| (0008,0022) | AcquisitionDate | 収集日 * | 撮影の日 |
| (0008,0032) | AcquisitionTime | 収集時刻 | 撮影の時刻 |
| (0008,0023) | ContentDate | 画像作成日 * | 画像を作った日 |
| (0008,0033) | ContentTime | 画像作成時刻 * | 画像を作った時刻 |
| (0020,0032) | ImagePositionPatient | 画像位置（患者） | 位置 |
| (0020,0037) | ImageOrientationPatient | 画像方向（患者） | 向き |
| (0020,1041) | SliceLocation | スライス位置 | スライスの位置 |
| (0018,0050) | SliceThickness | スライス厚 * | スライスの厚さ |

- 患者・検査・シリーズの単位の値（氏名・検査日など）は既定に入れない。見出しとサムネイルの並びに出ている。
- 転送構文（(0002,0010)）はファイルのメタ情報で、WADO-RS の `metadata` に入るとは限らないので既定に入れない。施設が足したときに値が無ければ「—」になる。
- 撮影の条件（管電圧 (0018,0060) など）はモダリティで違うので、既定に入れず施設が足す。

### 6. 画面の API：`GET /api/studies/{uid}/series/{series}/instances/{sop}/tags`

答えは `{ tags: [{ tag: "0008,0018", name: "SOPインスタンスUID", vr: "UI", value: "…" | null, length?: number }] }`。設定の順に、画像に無いタグも `vr: ""`・`value: null` で返す。値が 1024 文字を超えたときだけ `length`（全体の文字数）を付け、`value` は先頭の 1024 文字にする。

- 値の組み立ては、いまの `src/lib/all-values.ts` の `valueText`（バイナリ・SQ・PN・複数の値）を使い、設定のタグの選び出し・タグ名・長さの切り方を足す。「すべてのタグ」はいまの `…/values` を使い、同じ表の部品でタグ名の列も出す（名前の分かるものだけ）。
- 文字数は Unicode の符号位置で数える（サロゲートの組を割らない）。長い値の切り方は、値の全部の `…/values`（すべてのタグと「DICOM タグ」の検査単位）にも同じく当てる（spec の「長い値とバイナリの値」は画面の API の全部に掛かる）。
- 権限・UID の確かめ・操作ログは、いまの `…/values` と同じ形にし、`detail` に `set: "configured"` を足す。`…/values` の `detail` には `set: "all"` を足す。

### 7. タグ名

タグ名は日本語で出す。BFF の小さな表（既定の 25 と、患者・検査・シリーズの主なタグ）に、タグごとの日本語の名前と DICOM の keyword を持ち、日本語の名前を返す。表に無いタグはタグ名を空にする（私的タグを含む）。DICOM の辞書の依存（ライブラリ）は足さない。

- 訳は次の 2 つを参考にして決め、表を丸ごとは写さない。
  - リベルワークス「標準DICOM画像タグセット一覧」 <https://www.liberworks.co.jp/know/know_dicomTag.html>（タグごとの日本語の属性名。2026-10-23 に読んだ）
  - Sonic DICOM「DICOM用語集」 <https://ja.sonicdicom.com/dicom-glossary/>（タグの例と属性名。2026-10-23 に読んだ）
- 参考の訳と画面の用語集（`docs/spec.md` の 2.2）が違うときは、用語集を先にする。同じものを画面の別の場所で別の言葉にしないため。
  - 例：Instance は画面で「画像」と呼ぶので「インスタンス番号」でなく「画像番号」。Study Description は「検査記述」でなく「検査名」、Series Description は「シリーズ名」、Patient's Name は「氏名」、Patient ID は「患者ID」。
  - Referring Physician's Name は「紹介医」にする（参考の訳「照会医師の名前」を短くした）。
- 日付は用語集の「検査日」に合わせて「〜日付」でなく「〜日」にし、数は「〜の数」「行」でなく「〜数」にする。
- 参考に無い訳（RescaleIntercept・RescaleSlope）と、参考の訳では意味が伝わりにくいもの（ContentDate の「内容日付」）は、ここで決めた（5 の表の *）。
- 決めた訳は、`docs/spec.md` の 2.2 の用語集に「タグ名」の表として足す。

### 8. 日本語の値

BFF は文字コードを読み替えない。Orthanc は SpecificCharacterSet（`ISO_IR 192`・`ISO 2022 IR 87`・`ISO 2022 IR 13` など）に従って値を Unicode に直し、DICOM JSON（UTF-8）で返す。画面は受けた文字をそのまま出す。SpecificCharacterSet が無い画像は Orthanc の `DefaultEncoding` で読まれる（施設の Orthanc の設定）。

### 9. 権限と操作ログ

新しい権限は足さず、`dicom.all_values` を使う。「主なタグ」は値の全部の一部で、全部を見られる役割に限れば十分。設定に患者の値のタグを書いても、見られるのは値の全部を見られる役割だけになる。

## Risks / Trade-offs

- [Orthanc が ISO 2022 IR 87 の値を期待どおりに直すか、まだ実の Orthanc で測っていない] → 合成の患者の ISO 2022 IR 87 の画像を結合の試験（`docs/integration-test.md`）で Orthanc に入れ、`metadata` の値を確かめる。結果をモックの見本に写す。
- [画像の多いシリーズ（数千枚）で、一覧の QIDO-RS が遅い・一覧が長い] → 一覧はいまの画像単位と同じ要求で、遅さは変わらない。一覧の中でスクロールさせる。数千枚で遅ければ、仮想の一覧を別の change にする。
- [「DICOM タグ」から画像単位を外すと、慣れた利用者が迷う] → 画面の言葉と仕様書を同じ PR で直し、README の機能の説明に、画像ごとのタグはサムネイルから見ることを書く。
- [設定を変えるには再起動が要る] → 導入の時に決める値なので受け入れる。要望が出たら管理の画面へ移す（Decisions の 3）。
- [設定に患者の値のタグを書けば、画像の場所にも患者の値が出る] → 見られるのは `dicom.all_values` の役割だけで、いまの「DICOM タグ」と同じ範囲。

## Migration Plan

- データベースは変えない。`INSTANCE_TAGS` は省けるので、いまの設定のまま版を上げても起動する。
- 戻すときは前の版のイメージに戻す。`INSTANCE_TAGS` を書いたままでも、前の版は知らない変数を読まないので起動する。
