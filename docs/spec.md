# tsunagi-dicom（つなぎだいこむ）仕様書

> 状態：設計の段（2026-10-18）。実装はまだ無い。段の進め方は「6. 段階」。

DICOMweb に対応した画像サーバー（Orthanc など）を**改造せずにバックエンドとして使い**、日本の医療機関の画像の見方に合わせた一覧・時系列・ビューアの選び分けを提供する、独立した Web の画面と BFF（Backend For Frontend）。

> **Not for Diagnostic Use / 非医療機器。** 研究・教育・検証のためのソフトウェアで、医療機器としての承認・認証を受けていない。

## 1. 原則

1. **バックエンドを改造しない。** 画像サーバーとビューアのソースには手を入れない。つなぎ先はすべて設定（環境変数）で決める。画像サーバーとビューアが別のサーバーにあってもよい。
2. **標準を先に使う。** 検索・取得・表示の基本は DICOMweb（QIDO-RS・WADO-RS）で書く。Orthanc にしか無い機能（ワークリスト・分割・結合・統計・DICOM の作成）は「Orthanc のときだけ有効」な部品に分ける。
3. **どこでも動く。** 特定の施設・ネットワーク・名前に依らない。施設ごとの値は設定で渡す。リポジトリには例の名前（`pacs.example.org`）だけを書く。
4. **安全を既定にする。** 既定の設定は認証が有効。証明書の確かめは切らない（自前の CA は `*_CA_FILE` で渡す）。秘密の値に既定値を置かない。
5. **ガイドラインに沿った機能を持つが、「準拠」とは言わない。** 厚労省のガイドライン（第7.0版）の項目のうち、アプリケーションで担える部分を実装し、その対応表を文書と画面で示す。ガイドラインへの適合は、運用を含めて各施設が判断するもので、このソフトウェアだけで「準拠」とはならない。
6. **商用の製品の名前・画像・ロゴを使わない。** アイコンは Lucide、見た目は Tailwind CSS で作る。文書でも商用の製品の名前を出さない（「日本の医療機関で広く使われている画像の閲覧の慣習」のように書く）。
7. **医療の現場の言葉を言い換えない。** 未検像・検像済・未読・既読・緊急・簡易レポートなど、医療関係者のよく知っている言葉をそのまま使う（別の言葉にすると、使うときに混乱する）。診療に使うかどうかは使い手の判断で、機能ごとに「診断用ではない」の断り書きは足さない（共通の「非医療機器」の表示は出す）。

## 2. 技術の構成

| 項目 | 選ぶもの | 理由・条件 |
|---|---|---|
| 画面と BFF | Next.js（App Router・TypeScript・`output: 'standalone'`） | 画面とサーバーの処理を1つのコンテナにまとめられる |
| 見た目 | Tailwind CSS・shadcn/ui（Radix UI）・Lucide | 商用の素材を使わない |
| データの取得 | TanStack Query | |
| BFF のデータベース | SQLite（WAL）＋ Prisma。PostgreSQL に切り替えられる | 小さく始め、件数が増えたら替える |
| 試験 | Vitest（単体）・Playwright（画面。モックのバックエンドに対して流す） | CI でもクラウドの開発環境でも、社内の画像サーバー無しで流せる |
| 配布 | コンテナのイメージ（GHCR）。版の番号のタグと digest で配る | 前の版にすぐ戻せる |
| ライセンス | MIT | 画像サーバーとは REST・DICOMweb でやり取りするだけで、そのコードを取り込まない |

画面の見た目の基準：暗い地（`#121417`〜`#1a1d21`）、文字 `#e6edf3`、ラベル `#8a949e`、値 `#ffffff`（太字）、基準の文字 14px（0.875rem）、行間 1.5。

画面の言葉：最初は日本語だけ。ほかの言葉への切り替えは後の段で決める。文書は日本語を主にし、README は日本語と英語。

### 2.1 設定（`.env.example`）

設定の正本はリポジトリの [`.env.example`](../.env.example)（値は例の名前だけ。秘密は空）。ここには要点だけを書く。

| | `LOGIN_LOCK_THRESHOLD`・`LOGIN_LOCK_MINUTES` | 続けて失敗したら、一定時間ログインできなくする（既定 5 回・15 分） |
| | `SCREEN_LOCK_MINUTES` | 操作が無いときの画面のロック（既定 15 分。0 で無効） |

| | `TZ` | 既定 `Asia/Tokyo` |

## 3. 機能（6つの部品）

### 3.1 検査の一覧
- **すぐ絞れる見出し**：検査日（今日・昨日・1週間・今月・全期間・期間の指定）、モダリティ（すべて・CT・MR・CR/DX・US・ES・MG・DOC・SR。色分け）、状態（未検像・検像済・未読・既読・緊急・ブックマーク）、横断の検索（患者 ID・氏名の漢字・かな・英字・受付番号・検査の記述）。
  - 状態（検像・読影・緊急・ブックマーク）は BFF のデータベースに持つ。画像サーバーの DICOM の値は書き換えない。
- **読みやすい一覧（14px）と日本式の整形**
  - **氏名の解析**：`Alphabetic=Ideographic=Phonetic` の標準の形のほか、崩れた形（ローマ字が無い、漢字が空、空白で区切る、半角カナ、敬称つき、前後の空白、4つ目以降の `=`）でも、エラーにせず読める字だけを出す。漢字の氏名（14px・太字・白）とかなの氏名（12px・灰色）に分けて出す。試験は `docs/patient-name-test-cases.md` の 30 の形（元の 23 の形に、空の入力などを足したもの）から始める。
  - **和暦・年齢・性別**：`1975/05/10（昭和50年・51歳・男）`。年齢は検査日の時点で数える。
  - **代表のサムネイルと、シリーズ数・画像数**。
- **詳細のパネル**（行のクリックで、動きの遅れ無しに開く）
  - 左：検査の情報（2列）、右：患者の情報（2列）、下：シリーズごとのサムネイルの並び。値は `…` で切らない。
  - StudyInstanceUID・SeriesInstanceUID は、行の幅いっぱいに 0.75rem・等幅・`#777` で控えめに出し、コピーのボタンを付ける。

### 3.2 ビューアの選び分けと記憶
- **ビューアの部品（ViewerAdapter）**：設定で URL が与えられたもの（Weasis は `VIEWER_WEASIS_ENABLED=true` のとき）だけを出す。
  - `ohif`：OHIF Viewer v3（CT・MR の多断面・過去との比較）
  - `stone`：Stone Web Viewer（単純 X 線・超音波の速い表示）
  - `volview`：VolView（3D の表示）
  - `weasis`：Weasis（`weasis://`。手元のアプリ。DICOMweb で開く。**段 4 の後**）
  - `dicomweb`：研究の道具（3D Slicer など）に渡す DICOMweb の URL のコピー
- **選び方の3段**
  1. **その場で選ぶ**：行の `[▶ 開く | ▾]` から、ビューアを選んで別のタブで開く。詳細のパネルのシリーズからも開ける。
  2. **検査ごとに覚える**：「この検査は次から VolView」を StudyInstanceUID ごとに保存。行に `[既定: VolView]` を出し、ダブルクリックでそれを開く。
  3. **モダリティごとの既定**：覚えが無い検査は、モダリティの既定（例：CT・MR は OHIF、CR・DX・US は Stone）で開く。既定は管理の画面で変える。

### 3.3 患者ごとの時系列
- **表**：縦がモダリティ（CT・MR・CR/DX・US・ES・DOC・所見）、横が検査日。セルに代表のサムネイル・検査の記述・枚数・既定のビューア・所見の有無を出す。ダブルクリックで既定のビューア、▾ で別のビューア。
- **2つの検査の比較**：2つのセルを選んで「比較（1×2）」。2つの StudyInstanceUID を渡してビューアを開く（OHIF の複数の検査の指定を使う。**動作は実装の前に確かめる**）。

### 3.4 簡易レポートと文書
- **簡易レポート**：検査ごとに「検査目的」「画像所見」「結論・研究メモ」「読影の状態（未読・既読）」と、キー画像（SOPInstanceUID）を保存する。医療の現場で使われている言葉をそのまま使う（言い換えると、使うときに混乱する。原則 7）。
- **文書**（Orthanc のときだけ）：PDF・JPEG・PNG を落とすと、Orthanc の `/tools/create-dicom` で DICOM（Encapsulated PDF・Secondary Capture）にして入れる。時系列の DOC の行から画面の中で見る。文字のコードは UTF-8（ISO_IR 192）。

### 3.5 検像・取り込み・ワークリスト（Orthanc のときだけ）
- **他の施設のデータの取り込み**：取り込む前に元の値を一覧で出し、自施設の患者 ID・氏名（漢字・かな・英字）・受付番号に書き換えて取り込む。文字のコードは UTF-8（ISO_IR 192）にそろえる。
- **日本語の値の修正・シリーズの分割・検査の結合**：氏名を漢字・かな・英字に分けて直す画面。Orthanc の `/studies/{id}/split`・`/merge` を、確かめの画面を挟んで流す。
- **ワークリスト**：Orthanc の Worklists のプラグインで、予約の一覧・作成・削除。**作るときの文字のコードは UTF-8 だけにする**（JIS を指定すると漢字が黙って消えることを 2026-10-18 に確かめた。下の「既知の制約」）。

## 4. 開発用の認証の切り替え（`AUTH_MODE=dev`）
- ログインを省き、画面の上に `[検証モード｜役割：管理者・医師・技師・閲覧]` の切り替えを出す。画面の全体に「検証モード」の帯を出し続ける。
- **書き込み（修正・削除・取り込み・ワークリストの作成）は止める。** 書き込みも試すときは `DEV_ALLOW_WRITE=true` を足す。
- `AUTH_MODE=dev` は `BACKEND_MOCK=true` か、接続元を `127.0.0.1` などに限ったときだけ起動する（どちらでもなければ起動しない）。
- 監査の記録は、検証モードでも取る（役割の切り替えも記録する）。

## 5. 公開と配布
- リポジトリは公開。**社内の名前・秘密・実の患者のデータを入れない。** 見本のデータ（`tests/fixtures`）は合成の患者だけで、公開の前に中身を人が確かめる。
- CI（GitHub Actions）：PR で lint・型・Vitest・Playwright（モック）。`main` への merge と版のタグで、イメージを作って GHCR へ。**イメージを作る仕事にだけ `permissions: packages: write`** を付ける（リポジトリ全体を読み書きにしない）。
- イメージのタグ：`vX.Y.Z` と `sha-<短い hash>`。`latest` は付けてもよいが、配備は版のタグか digest を指定する。
- 文書：README（日本語と英語）、`docs/spec.md`（この文書）、`docs/guideline-mapping.md`、`docs/patient-name-test-cases.md`、`AGENTS.md`（開発の決まり。`CLAUDE.md` は `@AGENTS.md` の1行）。
- 「DICOM® は NEMA の登録商標」の一文を README に書く。

## 7. 既知の制約（2026-10-18 時点の実測）
- Orthanc の Worklists のプラグインで、REST でワークリストを作るとき、SpecificCharacterSet に `ISO 2022 IR 87` を指定すると漢字とかなが消える（エラーにならない）。`ISO 2022 IR 13\ISO 2022 IR 87` は断られる（400 `Unknown encoding`）。指定しなければ UTF-8（ISO_IR 192）で正しく入る。UTF-8 に対応しない古い装置へ JIS で渡すことは、この段の範囲外。
- Orthanc の設定の氏名の整形（1本の正規表現）では直せない形が3つある（`^Taro` の頭の空白など）。このアプリの氏名の解析では直す。
