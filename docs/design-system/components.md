# 部品

画面は、ここにある部品だけで組む。各部品は「使う場面」「挙動と数値」「使わない場面」「NG と代わり」「理由」を持つ。数値の元は [tokens.md](tokens.md)。実装の場所は [README.md](README.md) の表。

確認の窓と、浮くメニュー（ユーザーのメニューなど）は、標準の機構（HTML の `dialog` と `popover`）に任せ、自作しない。背景の暗幕・フォーカスの閉じ込め・Esc で閉じる動きを自前で書かない。

## 上の帯

- **使う場面：** 場所をまたいで使う道具。患者ID・受付番号での直接の検索、接続の状態、表示（明るい地・暗い地）、ユーザーのメニュー。
- **挙動と数値：** 高さ 48px、全画面で同じ、固定。地は `surface`、下に 1px の `border`。左から、製品名・（空き）・直接の検索・接続の状態・表示・ユーザー。右側は 5 つまで。
- **接続の状態：** 閉じているときは、全体の状態を 1 つの札（接続中・一部が接続不可）で出す。押すと、標準の `popover` で中身（相手ごとの名前・状態の札・時刻、「接続確認」）が出る（外を押す・Esc で閉じる）。一部が接続できないときは、閉じたままでも札が替わる。相手を知らせる別の帯（情報バー）は置かない。
- **使わない場面：** 画面への道（ナビに置く）と、画面の操作（見出しの行に置く）。
- **NG と代わり：** 上の帯に画面の項目を並べない → 左のナビに置く。画面の操作を上の帯に置かない → 見出しの行の右に置く。上の帯の下に別の帯を足さない → 接続の状態の中身に入れる。
- **理由：** 項目が増える段で上の帯が溢れる。道具と道を分けると、どの画面でも同じ位置に同じものがある。
- **3 製品の並び（組み方は [parts.md](parts.md)）：** 左は ナビの開閉 → 製品名 → 版（text-xs・`label`。3 製品とも出す）。右は 直接の検索 → 接続の状態 → 表示 → 利用者（表示名と、ユーザーID〔役割〕を 2 行）→ 画面ロック → ログアウト。無い項目は詰め、順は変えない（ログインの無い dicom-test-generator と ris-emulator は右端が表示）。表示は絵の押しボタン 1 つ（押すたびに明るい地と暗い地を替える。`aria-label` は「明るい地と暗い地を切り替える」）。画面ロックとログアウトはユーザーのメニューに畳まず、帯に直に置く（離席の前に 1 回で押せる）。右側の数は、直接の検索を除いて 5 つ。ris-emulator の MWL の待ち受けは、接続の状態の中身に入れる。

## 左のナビ

- **使う場面：** 仕事の単位への道。群は「業務」「接続」「管理」の 3 つまで、1 階層。件数は要対応のものだけ右に出す。
- **挙動と数値：** 幅 208px（閉じると 56px）、項目の高さ 32px。現在の画面は `selected` の地・左に 3px の `ring`（暗い地でも地との対比 3:1 を保つため、主の色ではなく ring）・太字。項目の絵は、頁を切り替える待ちの間、待ちの印に替わる（閉じた幅でも見える）。画面の高さを超えるときは、ナビの中でスクロールする。1 群 5 項目、全体 8 項目まで。役割に許されない項目は出さない。空の群は出さない。
- **使わない場面：** 操作（ボタン）・絞り込み・入れ子のメニュー。
- **NG と代わり：** 動詞の項目名（「作る」「送る」）→ 用語集の名詞にして、動詞は画面の中のボタンにする。項目名は用語集の語（検査一覧・受信一覧・接続先など）で、画面の題と同じ語にする。上の帯のタブで入り口を並べない → 左のナビに置く。
- **理由：** 画面の道と画面の操作を混ぜると、押したものが移動なのか実行なのか分からなくなる。

## パンくず

- **使う場面：** 患者や検査の下の画面（詳細・送信・エクスポート）で、いまの場所と戻り先を示す。
- **挙動と数値：** 見出しの行の上。最後の項目は現在地で、リンクにしない。
- **使わない場面：** 一覧の画面。ナビの現在地だけで足りる。

## 患者バナー

- **使う場面：** 患者のある画面すべて。見出しの下、検索の帯や区画より上。
- **挙動と数値：** 地は `surface`、枠 1px `border`、角 md。氏名（text-lg、かなを下に text-xs）→ 患者ID → 生年月日・性別 → 受付番号 → 検査日時 → モダリティ・検査名。右端に状態の札と、注意の枠（任意。枠は `danger`）。注意は枠の中に小さな札を 1 行で並べ、縦を取る帯にしない。枠と札の形だけを決めてあり、どの注意を出すかは未定。
- **使わない場面：** 患者のいない画面（一覧・設定）。値が無い項目も詰めず、「—」で場所を残す（下の「決まった形」）。
- **NG と代わり：** 画面ごとに患者の見出しを作り直さない → 同じ部品を使う。検査の詳細の見出し（氏名・かな・患者ID を数行で並べる形）もこの部品に替える。和暦・紹介医・英字氏名・Study ID・シリーズ数と画像数はバナーに足さず、「検査の情報」に置く。
- **理由：** どの画面でも同じ位置に同じ並びで出れば、誰の検査かを取り違えにくい。
- **決まった形（組み方は [parts.md](parts.md)）：** 項目と大きさを中身で変えない。形は 2 つだけ：右の区画（一覧＋右に詳細）は 2 行の格子（1 行目 氏名〔かな〕・患者ID・生年月日と性別、2 行目 状態の札・受付番号・検査日時・モダリティと検査名。各行 40px。患者ID・受付番号が収まらないときだけ、その行を高くし、項目の位置は変えない）、詳細だけの画面は 1 行（氏名・患者ID・生年月日と性別・受付番号・検査日時・モダリティと検査名・右端に状態の札）。値の無い項目も項目名を残し、値を「—」（`label` の色）にする。かなとモダリティ・検査名は 1 行で切り、全文は `title` で出す。詳細の区画では区画の上に固定する（スクロールで消さない）。HTML とクラスは parts.md の「患者バナー（`.fb`）」。

## 検査の情報

- **使う場面：** 検査の詳細（右の区画と、詳細だけの画面）で、患者バナーの下。バナーに足さない、毎回は見ない値。
- **挙動と数値：** 3 列×2 行の格子（各行 40px）に、英字氏名・生年月日（和暦）・紹介医・Study ID・シリーズ数と画像数 の順で置く（6 つ目の升は空ける）。値の無い項目は「—」。並びは 患者バナー → 検査の情報 → Study UID の行 → 操作の行。組み方は parts.md の「検査の情報（`.finfo`）と UID の行（`.uidrow`）」。
- **NG と代わり：** 値の無い項目を詰めない → 「—」で場所を残す（詰めると、検査ごとに項目の位置が替わる）。
- **理由：** 検査を替えたときに、同じ項目が同じ位置にあれば、目で探し直さずに比べられる。

## 検索の帯（条件）

- **使う場面：** 一覧の上。主な条件を 1 行に、詳しい条件は帯の下段に。
- **挙動と数値：** 地は `muted-strong`、角 md。左に条件、右に「検索」（主）と「条件をクリア」（副）。条件が 2 つ以下なら見出しの行に置いてよい。入力のたびに絞り込む画面（検査の一覧）は、「検索」を置かず、「条件をクリア」だけを右に置く（条件が無いときは薄く押せない形で、位置は動かさない）。件数を添えた選択肢は、件数が 0 のものを薄く（`label`）するが、押せるままにする（押すと 0 件になる、と分かる）。
- **使わない場面：** 入力の画面の項目（区画に置く）。
- **NG と代わり：** 検索の欄の幅を中身で変えない → 幅を固定する。件数や自動更新を条件の行に混ぜない → 件数の行に置く。
- **理由：** 欄が空かどうかで後ろの要素の位置が動くと、目で探し直すことになる。

## 件数の行

- **使う場面：** 一覧の上、検索の帯の下に 1 行。件数と、並びの補足・自動更新の状態。
- **挙動と数値：** 高さ 28px 以上で常に確保し、中身が空でも位置を変えない。左に件数（`text-lg`・太字）と「件」、右に補足（text-xs・`label`）。読み込みの間は件数を「—」にする。自動更新で新しい行の差し込みを待っている間（ポインタが一覧の上にある間など。spec の 3.1）は、補足の左に「新着 n 件」の枠のボタン（小 24px）を出し、押すと差し込む。
- **使わない場面：** 条件の入力。
- **NG と代わり：** 件数を検索の帯の右に置かない → 件数の行に置く。
- **理由：** 条件の入力と結果の要約を分けると、条件が増えても件数の位置が動かない。

## UID の行

- **使う場面：** StudyInstanceUID・SeriesInstanceUID・SOPInstanceUID など、長い識別子を出す行。検査の UID は詳細の見出しの最後の行、シリーズの UID は画像の場所の見出し、画像の UID は選んだ画像のタグの表の 1 行目（下の「画像の UID」）。
- **挙動と数値：** 項目名（text-xs・`label`）、UID（mono-uid 12px・`label`・行の幅いっぱいに折り返す）、写すボタン（枠なし・小）の順。ボタンは UID のすぐ右（値と同じ行の右隣。長くて折り返すときは最後の行の末尾）に置き、行の右端に離さない。UID の値そのものを押しても写せる（文字をドラッグで選んだときは写さない）。写したら、値の地を一瞬（1.5 秒）`selected` にして、ボタンの右に「コピーしました」を出し、読み上げにも知らせる。常に出し、開け閉めしない。
- **使わない場面：** 値を比べる表（タグの表に入れる）。
- **NG と代わり：** UID を開け閉めのボタンの中に隠さない → 置き場の見出しに常に出す。同じ UID を 2 か所に出さない。
- **理由：** UID は照合のために写して使う。開け閉めの手間は、使うたびの操作になる。
- **画像の UID（組み方は [parts.md](parts.md)）：** SOPInstanceUID は表の上の行に置かず、タグの表の 1 行目に (0008,0018) を固定して（主なタグに入っていなくても出す）、写すボタンをその行の値の後ろに置く。

## タグの切り替え

- **使う場面：** 画像の場所で、同じ場所に出す表を切り替える。画像に関するタグだけ：主なタグ（設定のタグ）・すべてのタグ（その画像の値の全部）。
- **挙動と数値：** 高さ 28px の並び（`aria-pressed` と地の色で選択を示す）。切り替えても、並びの位置は動かさない。画像の一覧が読めない・空のときは出さない。検査のタグ（検査単位の要約）は画像に関わらないので、ここに入れず、Study UID の行の右に置く「検査のタグ」のボタン（`aria-expanded`。小・枠）で、見出しの下に表を開け閉めする。
- **使わない場面：** 画面の切り替え（ナビを使う）。詳細の中の別の区画への切り替え（区画を並べる）。画像に関わらない値の表。
- **NG と代わり：** 同じ役目の入口を 2 つ持たない（詳細の下に別のタグのボタンを置かない）。画像のタグの切り替えに、画像に関わらない検査のタグを混ぜない → Study UID の横のボタンから開く。
- **理由：** 情報の入口が 2 つあると、どちらが正か分からなくなる。切り替えの中に画像に関わらない物が混ざると、いま見ている値が何の値か分からない。

## 一覧の表

- **使う場面：** 件数の行（左上）→ 表 → ページ送り（左に件数、右にページの操作）。
- **挙動と数値：** 行の高さ 28px（サムネイルや 2 行の氏名があるときは 40px）、見出しの行も 28px。見出しは並べ替えのボタン（いまの並びは太字と矢印）。選んだ行（クリックした行・矢印のキーで動かした行）は `selected-strong` の地と左 3px の `primary` で示し、`aria-selected="true"` を付ける。太字にしない（幅が変わるため）。hover の地（`muted`）は選んだ行より薄く、選んだ行には当てない。名前の列だけ太字にし、補足は 2 行目に小さく。見出しの行は地 `surface` で、表の中のスクロールでも残す。列は 8 つまで。行の全体を押せ、キーボード（`tabindex="0"`・Enter・Space）でも選べる。行の中のリンクやボタンを押しても、行は選ばない。自動更新で見ている行を動かさず、「新着 n 件」を出す。モダリティの印は左 4px の色の線の 1 つの形（parts.md の「一覧の表」）。
- **使わない場面：** 項目の少ない一覧（5 件ほど）はページ送りを省く。値を並べて見せるだけなら表でなく、項目名と値の対（区画）にする。
- **理由：** 一覧は探して選ぶ場所なので、密度を保ち、選んだ行を色と線の両方で示す（色だけに頼らない）。

## タグの表

- **使う場面：** 画像の場所と検査のタグで、DICOM のタグ（タグ・タグ名・VR・値）を並べる表。値を写して使うので、行を選べる。
- **挙動と数値（選ぶ）：** 選んだ行の見た目は「一覧の表」と同じ。マウスは、クリックで 1 行、Ctrl（Mac は Cmd）＋クリックで足す・外す、Shift＋クリックで範囲。キーボードは、上下の矢印で移って選び、Shift＋上下で範囲、Space で足す・外す、Ctrl／Cmd＋A で全部、Esc で外す。`role="grid"`・`aria-multiselectable` を付ける。表の上に 28px の行を常に出し（選びの有無で表を動かさない）、左に「n 行を選択」、右に「コピー」（件数つき。選ぶまで押せない）を置く。
- **挙動と数値（写す）：** 写す形式は、1 行 1 タグで列をタブで区切り、複数の行は改行でつなぐ。Ctrl／Cmd＋C と「コピー」は「全部の列」で写す。右クリックのメニュー（メニューのキー・Shift＋F10 でも開く）に、次の 3 つを置く。選んでいない行の上で右クリックしたときは、その行だけを選んでから出す。メニューは標準の `popover`（最前面・Esc で閉じる）。文字をドラッグで選んだときの写しは、ブラウザの動きに任せる。

  | メニューの項目 | 1 行の中身 | 例 |
  |---|---|---|
  | 全部の列 | `(tag)`・タグ名・VR・値 | `(0008,0020)` 検査日 DA 20261024（区切りはタブ） |
  | タグと値 | `(tag)`・値 | `(0008,0020)` 20261024 |
  | 値だけ | 値 | 20261024 |

  値の中のタブと改行は空白 1 つにする。1024 文字を超えて切って出した値は、切ったことを写した文にも「…（全 n 文字）」で残す。バイナリは出している「（バイナリ）」のまま写す。写したら、表の上の行に「n 行をコピーしました」を出す（読み上げにも知らせる）。
- **使わない場面：** 値を読むだけで写さない表（項目名と値の対で足りるもの）。
- **理由：** タグと値は、照合や問い合わせのために 1 行ずつ写して使う。右クリックは見つけにくいので、表の上にも同じ操作を置く。写す単位を行にし、キーボードでも同じ中身が取れるようにする。

## 状態の札

| 札 | 意味 | 色と印 | どこで使う |
|---|---|---|---|
| 予定 | まだ始まっていない | 灰の枠・○ | RIS の予約・DTG のワークリスト |
| 実施中 | 始まっていて終わっていない | `warning`・◐ | RIS の予約 |
| 完了 | 終わった | `success`・● | RIS の予約 |
| 取消 | なくなった。文字に線を引かない | 灰・— | RIS の予約 |
| 中止 | 途中でやめた | `danger`・■ | RIS の予約 |
| 送信待ち | 前の送信が終わるのを待っている | 灰の枠・○ | 3 製品の送信・RIS の HL7 |
| 送信中 | 送信している途中 | `warning`・◔ | 3 製品の送信 |
| 送信完了 | 送信できた | `success`・✓ | 3 製品の送信 |
| 送信失敗 | 送信できなかった | `danger`・✕ | 3 製品の送信 |
| 確認待ち・確認済・確認失敗 | 保管の確認の待ち・済み・失敗 | 灰・○／`success`・✓／`danger`・✕ | DTG の保管の確認・tsunagi の保管の確認 |
| 結果不明 | 届いたか分からない | `danger` の破線・？ | tsunagi の送信 |
| 受信中・受信完了 | 受け取っている途中・落ち着いた | `warning`・◔／`success`・✓ | tsunagi の受信一覧 |
| 確認中・成功・失敗 | 接続確認の途中・結果 | `warning`・◔／`success`・✓／`danger`・✕ | 接続先の表 |
| 待ち受け中・停止 | 相手から来るのを待っている・止まっている | `success`・●／`danger`・✕ | RIS の MWL・tsunagi の HL7 の受け口 |
| 知らせ | 良し悪しのない知らせ | 灰・◇ | DTG のワークリスト（撮影済み・別の装置）・RIS の照合（未照合・照合済み） |

`data-k` との対応は parts.md の「状態の札」。

- **使う場面：** 状態を 1 つの語で示すとき（表の状態の列・バナーの右端・要約の行）。語は短い名詞か動詞の形で、色は枠と印だけに付ける。製品ごとの札は、同じ形で製品の側が足す。
- **挙動と数値：** text-xs、角 3px、枠 1px。文字と印を必ず持つ。
- **使わない場面：** 強調や飾り。状態でないもの（モダリティなど）には使わない。
- **NG と代わり：** 文字を消して色だけにしない。色の塗りつぶしで強調しない → 枠と印にする。
- **理由：** 色だけでは見分けられない利用者がいる。状態にだけ色を使えば、色が出たところが状態の変化だと分かる。

## ボタン

- **使う場面：** 主は 1 画面に 1 つ（検索・登録・送信・撮影など、その画面の目的）。副はそれ以外。危険は削除・取り消しなど戻せない操作で、実行は確認の窓の中だけ塗りにする。
- **挙動と数値：** 高さ 32px（小 28px、一覧の行内 24px）、角 sm。主は `primary` の地・白い字、副は白い地・`border-input` の枠、枠なしは地なし。hover は `hover`（主は `primary-hover`）、押している間は `pressed`（主は `primary-active`）で、1px 沈む。無効は薄く、理由を近くに書く。フォーカスは 2px の `ring`。
- **使わない場面：** 移動（リンクにする）。
- **操作の行：** 詳細の操作は 1 行にそろえ、左から主・副の順に置く。戻せない操作（削除）は、ほかの操作から間をあけて右端に離す（日々の操作の真ん中に置かない）。
- **NG と代わり：** 同じ画面に主を 2 つ置かない。一覧の行の中のボタンを主にしない（行の数だけ主が並ぶ）→ 白地・枠の副にし、主は詳細の操作の行に 1 つだけ置く。ボタンの名前を「OK」「はい」にしない → 体言にする（検索・登録・送信・撮影）。動詞にしてよいのは、慣用の「開く」「閉じる」「キャンセル」「ログイン」「ログアウト」と、確かめの画面の実行（「送信する」「削除する」）と、対になる選択だけ（[glossary.md](glossary.md) の使い分け 2）。
- **理由：** 主が 1 つなら、次に押すものが一目で分かる。名前が動作を言っていれば、確認の窓を読まずに結果が分かる。

## 入力欄

- **使う場面：** 項目名は上に小さく。必須は項目名の横に「必須」と書く。誤りは入力欄の下に 1 行（印と文字。読み上げない。「知らせ」の節）、枠は `danger`。補足は入力欄の下に 1 行。
- **挙動と数値：** 高さ 32px、角 sm、枠 `border-input`。
- **使わない場面：** 項目名を入力欄の中の薄い文字（placeholder）だけにしない。placeholder は例の値だけ。
- **理由：** 入力すると placeholder は消える。項目名が消えると、何を入れる欄か分からなくなる。

## 確認の窓

- **使う場面：** 戻せない操作（削除・上書き・送信前の確かめ）の最後の 1 回。戻せても、権限を変える操作（役割の変更・ユーザーを無効にする・二要素認証のリセット）は必ず挟む（選択欄はホイールや矢印のキーでも変わり、気づかずに権限が変わるため）。
- **挙動と数値：** 題は「対象＋動詞」の疑問（対象を見分ける氏名・検査名・件数を入れる）、本文は「何が・どうなる・戻せるか」を 1〜2 文。キャンセルを左、実行を右（実行は動詞「削除する」）。文の書き方は [writing.md](writing.md)。初期のフォーカスはキャンセル。角 lg、影 lg。
- **使わない場面：** 戻せる操作・成功の知らせ。窓の中に入力欄を重ねない（入力は画面で行う）。
- **理由：** 最後の 1 回だけ止めるから、止まる意味が残る。

## 知らせ

- **使う場面：** 操作の結果と、画面全体に関わる注意。画面の上（見出しの下）か、結果が出る区画の上に置く。
- **挙動と数値：** 左に 4px の状態の色、印と文字。**画面の上の誤りの知らせだけ** `role="alert"` で読み上げる。文の書き方は [writing.md](writing.md)。
- **使わない場面：** 入力欄ごとの誤り（入力欄の下に出す）。画面の説明や使い方の案内。
- **入力欄の下の誤り：** 欄の下に印と文を 1 行出す。読み上げない（`role="alert"` を付けない）。欄には `aria-invalid="true"` と、文を指す `aria-describedby` を付け、欄に移ったときに読まれるようにする。画面の上の知らせと同じ文を使う。

## 空の状態

- **使う場面：** 検索の結果が 0 件、または記録がまだ無いとき。
- **挙動と数値：** 1 行目に事実、2 行目に次の手、操作は 1 つまで。内側 32px。表の枠と見出しの行は出したままにする。
- **使わない場面：** 読み込みに失敗したとき（誤りの知らせを使う）。

## 読み込み中

- **使う場面：** 表・詳細が読み込まれるまで。
- **挙動と数値：** 表の高さを保つよう、行の形の灰の帯を置く。動きは、動きの設定が「減らす」なら止める。
- **使わない場面：** 操作の結果を待つとき（その操作のボタンを無効にし、押した場所の横に「送信中」の札を出す）。

## 件数の要約（押せる）

- **使う場面：** 一覧の上で、状態ごとの件数を先に見せ、押すと絞り込む。状態が 3 つ以上ある一覧（予約・送信ジョブ）。
- **使わない場面：** 状態が無い一覧（検査）。件数が 1 つだけなら件数の行で足りる。その画面の判断に要らない状態は並べない。

## タブ・手順

- **使う場面：** タブは詳細の中の切り替えだけ（3〜4 つまで）。手順は、順番に進めて最後に戻せない操作がある画面（送信・インポート）。
- **挙動と数値：** タブの高さ 28px（押せる大きさの下限 24px 以上）。選んだタブは、下に 2px の `ring` の線・太字で示し、`aria-selected="true"` を付ける。左右の矢印のキーで移る（選んだタブだけがフォーカスを受ける）。中に押せる物が無い（読むだけの）パネルは、見えている間フォーカスを受け、キーボードで読み・スクロールできる（押せる物のあるパネルには、余分な止まり先を足さない）。選んでいないタブの中身も描いておき、見えなくする（開いた画像の場所などの状態を、切り替えても失わない）。
- **使わない場面：** 画面の切り替えにタブを使わない（ナビを使う）。

## 接続先の表

- **使う場面：** 接続先と、その接続確認の結果を並べる区画。tsunagi の接続先・dicom-test-generator の PACS の上の区画（送信先・ワークリスト）・ris-emulator の接続先（HL7 の送信先）。上の帯の接続の状態の中身と、同じ相手・同じ札にする。組み方は [parts.md](parts.md) の「接続先の表（`.conn`）」。
- **挙動と数値：** 区画の見出しに題、右に「すべて接続確認」（副）。登録できる製品だけ「追加」。列は 名称・種類（DICOM／HL7）・AEタイトル（HL7 は「—」）・ホスト名:ポート番号・最後の接続確認・操作（接続確認。登録できる製品は編集も）。「最後の接続確認」は、確かめていないとき「—」、確かめている間は札「確認中」（`warning`・◔。その行のボタンを押せなくする）、成功は札「成功」と時刻、失敗は札「失敗」と時刻と理由の 1 句。待ち受け（ris-emulator の MWL など、相手から来る側）は表に入れず、区画「待ち受け」に 名前・札「待ち受け中」（`success`・●）・住所を出す。
- **理由の 1 句：** 応答がありません・接続を断られました・AEタイトルが合いません・ホスト名を引けません の 4 つ。英語の誤りの文はそのまま出さず、記録（ログ）に残す。表の列は「なぜか」だけを残し（writing.md の狭い場所の決まりの例外。次にすることは押した直後の知らせに書く）、接続確認を押した直後は、区画の上に知らせ（何が起きたか・なぜか・次にすること。例「VIEW-WS02（AE: VIEWWS02）に接続できません。応答がありません。VIEW-WS02 の電源と、ホスト名・ポート番号を確かめてください。」）を出す。
- **NG と代わり：** 見出しの横に説明の文（登録はどこで行うか）を置かない → 追加・編集のボタンが無いことで分かる。結果の列に英語の誤りの文を出さない → 理由の 1 句にする。
- **理由：** 3 製品の接続確認は同じ操作なのに、結果の場所（ボタンの右・別の列）と語（応答なし・英語の文）が違う。同じ形なら、どの製品でも同じ場所を見れば足りる。

## 送受信の一覧

- **使う場面：** 送る側（dicom-test-generator の送信ジョブ・tsunagi の送信一覧）と受ける側（tsunagi の受信一覧・ris-emulator の未照合）。dicom-test-generator の送信ジョブと tsunagi の受信一覧は、同じ送信を両側から見る画面なので、同じ形にする。組み方は [parts.md](parts.md) の「送受信の一覧」。
- **挙動と数値：** 上から 状態の要約（押せる）→ 検索の帯 → 件数の行 → 表 → ページ送り（1 ページ 50 件）。送る側は、行を選ぶと下に詳細（一覧＋下に詳細と同じ）。受ける側は詳細を持たず、行の「検査一覧で表示」（ris-emulator は「照合」）で、その検査の画面へ移る。
  - 列の順：日時（受付日時／受信日時）・相手（送信先／送信元 AE）・患者ID・氏名・モダリティと検査名・画像数・状態・（送る側だけ）保管の確認・操作。dicom-test-generator の今の列のうち、ジョブ・検査日時・受付番号・完了日時は詳細へ移す。
  - 状態の語：送信待ち・送信中・送信完了・送信失敗・結果不明／受信中・受信完了（ris-emulator の MPPS は 実施中・完了・中止）。
  - 操作：送る側は 再送信（送信失敗）・届いたか確かめる（結果不明）、受ける側は 検査一覧で表示（ris-emulator は 照合）。
  - 絞り込み：期間（今日・昨日・過去7日・期間を指定）・相手・患者ID と氏名。状態は要約で絞る。
  - 読む上限：期間の中の件数が 1,000 件を超えたら、件数の行の上に注意の知らせ「受信が 1,000 件を超えたため、新しい 1,000 件だけを出しています。期間を狭めてください。」を出す。
- **NG と代わり：** 直近の決まった件数の中だけで絞らない（直近 100 件の中だけで絞る受信一覧にしない）→ 期間で読み、上限を超えたら知らせる。送る側と受ける側で列の順を変えない。
- **理由：** 送った側と受けた側を並べて見比べるとき、列の順と状態の語が同じなら、同じ行を目で追える。
