# メニューの決まり

## 置き方

| 場所 | 置くもの | 置かないもの | 上限 |
|---|---|---|---|
| 上の帯（左から） | ナビの開閉・製品名・（空き）・患者ID と受付番号の直接検索・接続の状態・表示（明るい地／暗い地）・ユーザーのメニュー | 画面への道・画面の操作 | 右側 5 つまで |
| 左のナビ | 仕事の単位（名詞 1 語）。群は「業務」「接続」「管理」。現在地は `selected` の地＋左の線＋太字 | 操作・絞り込み・2 階層目 | 1 群 5 項目、全体 8 項目 |
| 見出しの行の右 | その画面の操作。主は右端、危険な操作は間をあけてその左 | 画面への道 | 主 1・副 3 |
| ユーザーのメニュー | アカウント・ログアウト・（管理者の）役割の切り替え | 仕事の画面 | 5 項目 |

並べる順は、群の中では「毎日使う順」。「管理」の群は、役割に許される項目だけを出し、1 つも出せない群は出さない（個人設定は全員に出す）。**項目名は用語集（[glossary.md](glossary.md)）の語を使い、画面の題と同じ語にする**（検査一覧・受信一覧・接続先など。「〜の一覧」「〜管理」を付けてよい）。ボタンの名前は、用語集の使い分け 2 に従い、体言にする（開く・閉じる・キャンセルなどの慣用と、確かめの画面の実行〔「送信する」「削除する」〕だけが動詞）。

## 3 製品のメニュー

2026-10-25 に、入り口を上の帯のタブから左のナビへ移すと決めた。項目の名前は、今の画面の名前のまま移す。

| 製品 | 群 | 項目 |
|---|---|---|
| tsunagi-dicom | 業務／接続／管理 | 検査一覧・受信一覧／接続先／ビューア設定・ユーザー管理・個人設定 |
| ris-emulator | 業務 | 予約・予約作成・一括作成・未照合 |
| dicom-test-generator | 業務／接続／管理 | ワークリスト・撮影・送信ジョブ／送信先／設定 |

同じ意味は同じ語にし（「検査」「予約」「送信」）、製品に無い機能の名前は持ち込まない。RIS の「予約」は、予約の語が画面の題にもなる RIS の仕様の語（シミュレーターの語。glossary.md）なので、「〜一覧」を付けない。tsunagi の「接続先」（画像サーバーに登録した相手）と DTG の「送信先」（DTG が送信する相手）は別の機能なので、別の名前のままにする。tsunagi の保管の状態の画面は、できたときに「接続」の群へ足す。

## 現状との差

tsunagi-dicom は、左のナビ（`src/components/layout/side-nav.tsx`、項目は `nav-items.ts`）に移した。上の帯（`site-header.tsx`）は、ナビの開閉・製品名・表示・ユーザーのメニューだけを持つ。患者ID と受付番号の直接検索と、接続の状態は、まだ上の帯に無い（足すときは、機能の PR と同じ PR で足す）。ris-emulator と dicom-test-generator の今の上の帯は、上の項目をタブに並べている。左のナビへ移すとき、上の帯は製品名・直接検索・接続の状態・表示・ユーザーのメニューだけにする。RIS は予約の一覧の作り直し（型 B）と同じ PR で移し、DTG は別の PR で移す。新しい画面の項目は、上の帯に足さず、左のナビに足す。
