# 文言の書き方（誤り・知らせ・空の状態・確認の窓）

画面の文の書き方の決まり。語（送信・再送信・送信先・キャンセルなど）は [glossary.md](glossary.md) に従う。

## 規則

**誤り・知らせ・窓の文は、「何が起きたか」「なぜか」「利用者が次にすること」を、対象の名前を入れて、この順で書く。** 狭い場所では、「なぜか」と「次にすること」を残す。例外は 3 件：状態の札がもう「何が起きたか」を言っている行（札の隣の文は、なぜかと次にすることだけ）、原因が分からないとき（分からないと書く）、成功の知らせ（次にすることは、要るときだけ）。

理由：画面の文を読む人の目的は、操作を終えることで、文を理解することではない。公開されている画面の書き方の指針の多くが、事象・原因・対処の同じ組み立てを勧める。

## 型

| 場所 | 書くこと | 型 | 例 |
|---|---|---|---|
| 入力欄の下 | なぜ直すか＋直し方（1 行）。**読み上げない** | 項目名＋を＋動詞。欄ごとに別の文 | 予定日を入力してください。／氏名（かな）は全角のカタカナで入力してください。 |
| 画面の上の知らせ（誤り） | 結果＋直すこと。複数なら件数と一覧。**読み上げる**（`role="alert"`） | 入力欄の下の文と同じ文を使う | 登録できません。予定日を入力してください。 |
| 画面の上の知らせ（受け付け） | 受け付けたことと、結果を読む場所 | 〈対象〉を受け付けました。〈読む場所〉で分かります。 | VIEW-WS02 への送信を受け付けました。届いたかは、下の表の状態で分かります。 |
| 表の行の理由（札の隣） | なぜか＋次にすること | 札が事象を言うので、事象は繰り返さない | TEACHING につながりませんでした。つながりを確かめて、再送信してください。 |
| 結果不明 | 分からないこと＋確かめる対象と人＋それまで何ができないか | 成功とも失敗とも書かない | 届いたか分かりません。VIEW-WS02 にこの検査（412 枚）が届いているかを確かめるまで、同じ送信先へは送信できません。管理者でないユーザーには「管理者に確かめを頼んでください。」を添える。 |
| 確認の窓 | 題：対象＋動詞の疑問。本文：何がどうなるか＋戻せるか。ボタン：キャンセルと、実行の動詞 | 下の「確認の窓」 | 下の例 |
| 空の状態 | 1 行目：事実。2 行目：次の手（1 つまで） | 0 件と取得失敗を分ける | 下の例 |
| 読み込みの失敗 | 取得できなかったこと＋時刻＋次の手 | 空の状態と同じ見た目にしない | 予約を取得できませんでした（10:02）。もう一度取得してください。 |

入力欄の下の誤りは、読み上げの対象にしない。欄に移ったときに読まれるよう、欄に `aria-invalid="true"` と、文を指す `aria-describedby` を付ける。画面の上の知らせだけを `role="alert"` で読み上げる。同じ誤りを 2 回読み上げないため。

原因が分からないときは、「原因は分かりません。時間をおいて、やり直してください。」と書く。「予期しないエラー」「エラーが発生しました」とは書かない（総称で、何も伝えない）。

## 言い回し

| 良い | 悪い | 理由 |
|---|---|---|
| 予定日を入力してください。 | 入力に誤りがあります。／正しい値を入力してください。／予定日が正しくありません。 | 何が誤りか・何が正しいかが分からない |
| TEACHING につながりませんでした。 | 送信先に届かない | 対象の名前と原因が無い。名詞止めの断片で、届いたか届かないかも曖昧 |
| 412 枚を送信しました。 | 送信完了しました。 | 数が入るほうが、取り違えに気づける |
| この検査（試験 太郎・P000101）を削除しますか？ | この検査を削除しますか？／本当によろしいですか？ | 指示語だけでは、どの検査か分からない |
| 削除する／キャンセル | OK／はい | ボタンの名前だけで結果が分かる。取りやめは「キャンセル」（用語集で決まっている） |
| 時間をおいて、やり直してください。 | しばらくお待ちください。 | いつまで待つかが分からない言葉を避ける |

**使わない言葉：** 無効・不正・不正解、あなたが〜しなかった（責める言い方）、おっと・あれ・申し訳ありません・すみません、エラー（題や札に）、感嘆符、内部の用語と番号（HTTP の番号、Orthanc の仕事の状態名など。必要なら「詳細」の折りたたみに分ける）。**「正しくありません」「正しい値」も使わない。** 何が合わないかを書く（形式なら「全角のカタカナで」、範囲なら「1〜999 の数で」、足りないなら「〜を入力してください」）。書けないときは、書けるように画面の側（入力の制限・選択肢）を直す。

文末は「〜しました」「〜できません」「〜してください」を基本にし、「失敗しました」は、札が無い場所で事象を言うときだけ使う。

操作の名前は [glossary.md](glossary.md) に従う。再送信の操作は、ボタンの並びや一覧の題では「再送信」、結果が不明・失敗の行の横で 1 件だけ試す操作は「もう一度送る」でもよい。**同じ画面の中では、どちらかに揃える。**

## 確認の窓

題は「対象＋動詞」の疑問。本文は 1〜2 文で「何がどうなるか」と「戻せるか」。ボタンは右が実行の動詞（塗り。「削除する」「再送信する」）、左が「キャンセル」（初期のフォーカス）。対象を見分ける情報（氏名・患者ID・検査名・件数）を題か本文に入れる。

例（tsunagi-dicom の削除）：

- 題：検査 A2610240001（試験 太郎・CT 胸部 単純）を削除しますか？
- 本文：画像 412 枚が保管から消えます。削除したあとは戻せません。
- ボタン：キャンセル／削除する

窓にするのは、戻せない操作の最後の 1 回だけ。成功の知らせと戻せる操作には使わない。一括の操作は、件数と範囲を題に入れる。

例（一括の再送信）：

- 題：失敗 2 件を再送信しますか？
- 本文：TEACHING へ、あわせて 522 枚を再送信します。送信先に同じ画像が重なることがあります。
- ボタン：キャンセル／再送信する

## 空の状態

1 行目に事実、2 行目に次の手。0 件と取得の失敗は、文も見た目も分ける。

| 画面 | 1 行目 | 2 行目 |
|---|---|---|
| 検査の一覧（条件で 0 件） | 条件に合う検査はありません。 | 条件を変えるか、「条件をクリア」を押してください。 |
| ワークリスト（その日の予約が 0 件） | この日の予約はありません。 | 日付や装置の条件を変えて、もう一度検索してください。 |
| 送信ジョブ（記録が無い） | 送信ジョブはまだありません。 | 撮影して送信すると、ここに出ます。 |
| 取得の失敗（空ではない） | 予約を取得できませんでした（10:02）。 | もう一度取得してください。 |

## 医療の業務画面で特に守ること

- **結果が分からないとき、成功とも失敗とも書かない。** 再送信や再実行を勧めない。確かめる人と対象を書く。管理者でないユーザーには、確かめを管理者に頼むことを書く。
- **「受け付けた」と「届いた」を分ける。** 仕事を受け付けた知らせに、完了を思わせる語を使わない。
- **対象を指示語にしない。** 氏名と患者ID（または受付番号）、検査名、件数を入れる。
- **「すべて」「全部」は件数と一緒に出す。**
- **空と失敗を取り違えさせない。** 取得の時刻を添える。
- **おどけた言葉と謝罪を使わない。**
- **窓を増やさない。** 戻せない操作の最後の 1 回だけ。
- **色だけで伝えない。** 誤りは文字と印で示す（原則 6）。

## 新しい文を書いたときの確認表

1. 何が起きたかが、画面の言葉で分かるか（内部の用語・番号が無いか）
2. なぜか、分からないなら「分からない」と書いてあるか
3. 次にすることが、誰が・何を、まで書いてあるか
4. 対象の名前が入っているか（指示語だけではないか）
5. 使わない言葉（「正しくありません」を含む）が無いか
6. 同じ操作に、画面内で別の名前を付けていないか
7. 入力欄の下の文と、画面の上の文が、同じ文になっているか。読み上げは画面の上の知らせだけか
