# 検証のシナリオ

同じ 1 人の架空の患者・1 件の検査を、RIS の予約作成から tsunagi の送るまで 8 枚のワイヤーフレームに通す。8 枚の値は次の 1 件に揃えてあり、画面の間で食い違わない。

| 項目 | 値 |
|---|---|
| 患者 | 試験 太郎（シケン タロウ）・P000101・1970/04/01（56 歳）男 |
| 検査 | 受付番号 A2610240001・CT 胸部 単純（CT-CHEST）・呼吸器内科・装置 CT-1 |
| 日時 | 予定 2026/10/24 09:00・撮影 09:12（検査日時） |
| 画像 | 3 シリーズ・412 枚（180・180・52） |
| UID・AE | 検査 UID 2.25.168436582293106582614719232718384519123・RIS の AE RIS_EMU・DTG の装置の AE DTG_CT01 |

| 使い手 | 画面 | 手順 | 確かめたい要求 | 確かめたい項目 |
|---|---|---|---|---|
| 開発者 | RIS 予約作成（型 C） | 名簿から P000101 を選び、検査・予定・依頼を入れて登録 | 試す予約を最小限の入力で作る | 区画の順（患者・検査・予定・依頼）、必須の印、予定日の誤りが項目の下に出る |
| 開発者 | RIS 予約の一覧（型 B） | 患者 ID で探し、作った予約を選ぶ | 作った予約が予定の状態で出たかを確かめる | 患者 ID の検索、状態の札（予定）、右の区画の値が入力と同じ |
| 技師 | DTG ワークリスト（型 A） | 条件を変えず取得し、09:00 の行を選ぶ | RIS の予約を 1 件選んで撮影へ進む | 行の値が RIS と同じ、バナーと「撮影へ」 |
| 技師 | DTG 撮影（型 C） | 撮影の設定を確かめ、「撮影して送る」 | 予約の値を直さずに撮影して送る | 予約の値が読むだけ・412 枚・結果の知らせ |
| 開発者 | DTG 送信ジョブ（型 A） | ジョブ #41 を選ぶ | 送った検査が届いたかを、1 つの画面で確かめる | 確認済の札、412 / 412、詳細の UID |
| 開発者 | tsunagi 検査の一覧（型 A） | 検査日「今日」で試験 太郎の行を選ぶ | 送った検査が画像サーバーに届いたかを把握する | 検査日時 09:12・412 枚・モダリティ CT、詳細のバナーが DTG と同じ並び |
| 開発者 | tsunagi 検査の詳細 | シリーズと「すべての項目」を見る | 元の予約と値が同じかを確かめる | バナーの全項目・UID が DTG と同じ、シリーズ 3・412 枚 |
| 開発者 | tsunagi 送る（型 C） | 別の機器へ送る確かめの画面を通る | 検査を別の機器へ最小限の操作で送る | バナー・送り先・送る内容が同じ値、送ったあとの結果の札 |

確かめるのは見た目でなく、各行の「確かめたい要求」と「確かめたい項目」が、その画面の区画だけで足りるかどうか。足りない所は、型か区画の名前を直す。
